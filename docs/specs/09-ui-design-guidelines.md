# UI 设计规范

本文档定义 MythicRealm 当前 SwiftUI 原型的 UI 设计规范。后续新增或修改界面时默认遵循本规范，除非对应功能文档明确覆盖。

## 设计目标

- **移动端优先**：以 iPhone 15+ 竖屏为主要目标，所有页面必须在 iPhone 17 Pro 模拟器上完整可用。
- **信息优先**：这是 RPG 系统界面，不做营销式大 Hero；优先展示角色状态、数值、列表和操作。
- **暗色魔幻风**：背景以深紫/近黑为主，卡片使用低透明白色叠层，强调色来自系统含义和装备品质。
- **可扫读**：列表卡片、详情页、背包、结算页都要让玩家快速比较等级、战力、品质、风险和奖励。

## 布局规则

- 页面根容器使用全屏暗色背景，内容区域使用 `VStack`/`ScrollView` 组织。
- 顶部标题栏统一包含返回按钮、居中标题、右侧状态文本；左右区域必须固定或受限，标题使用 `frame(maxWidth: .infinity)`。
- 不允许依赖固定总宽度堆叠多个按钮或格子。横向元素必须使用 `maxWidth: .infinity`、`GridItem(.adaptive)` 或有限列数的 `LazyVGrid`。
- 竖向内容超过一屏时必须进入 `ScrollView`，底部固定按钮必须配合 `safeAreaInset` 或额外底部 padding，避免遮挡内容。
- 列表页左右边距使用 16-20pt；卡片内部 padding 使用 12-16pt；紧凑信息行间距使用 6-10pt。
- 在任何 iPhone 竖屏上，文字、按钮、装备格、掉落格不得被屏幕边缘裁切。

## 组件规范

### 卡片

- 卡片背景：`Color.white.opacity(0.04...0.06)`。
- 卡片圆角：10-16pt，默认 12pt。
- 重要卡片可加同色系描边，描边透明度 0.3-0.5。
- 不嵌套装饰性卡片；需要分组时使用 section 标题 + 单层卡片。

### 按钮

- 主操作按钮高度 44-48pt，宽度使用 `maxWidth: .infinity`。
- 两个并排按钮必须共享剩余宽度，不能使用固定 200pt 宽。
- 危险或挑战按钮用红色；确认或继续用绿色；背包/信息入口用蓝色；角色/稀有信息可用紫色。
- 列表卡片可整体作为按钮，右侧使用 `chevron.right` 提示可进入详情。

### 列表与网格

- 背包物品、掉落物品等格子使用 adaptive grid，避免固定列数在不同机型溢出。
- 装备槽在竖屏内最多 5 列，两行展示。
- 副本列表使用纵向卡片列表，卡片中展示名称、难度、推荐等级、推荐战力、风险状态和主要掉落。

### 详情页

- 详情页结构固定为：顶部栏、摘要卡片、风险提示、信息 section、底部主操作。
- 风险提示不阻断操作时使用橙色；真正禁用或失败才使用红色。
- 底部固定操作区必须有背景遮罩，且不遮挡 ScrollView 内容。

## 色彩语义

- 黄色：战力、金币、评分、重点奖励
- 红色：挑战、危险、伤害、低生命
- 蓝色：背包、信息、MP
- 绿色：继续、可用、恢复
- 紫色：角色、Boss、稀有/特殊状态
- 灰色：说明文本、次级状态、未装备槽

装备品质颜色沿用代码中的 `ItemQuality.color`，不要在具体页面重新定义品质色。

## 字体层级

- 页面标题：`headline`
- 主数值或评级：`title2` 到 48pt，只有结算评分可使用更大字号
- 卡片标题：`headline` 或 `subheadline.bold()`
- 常规说明：`caption` 或 13pt
- 辅助标签：`caption2` 或 9-11pt

文字必须 `lineLimit` 或允许换行；长文本在卡片内优先换行，不允许撑破宽度。

## 当前页面约定

- 主页：展示角色摘要，主入口只有副本和背包，底部放退出登录。
- 副本大厅：展示 5 个副本列表，风险副本用橙色描边和「高风险」标签。
- 副本详情：允许越级挑战，但必须显示等级/战力不足提示。
- 战斗页：保留文字战斗日志，顶部状态栏显示当前副本房间数。
- 结算页：评分、统计、掉落、底部按钮必须同屏可读；掉落较多时允许滚动。
- 背包页：装备槽两行展示，物品格使用自适应网格。

## 验收标准

每次 UI 改动后至少验证：

1. `xcodebuild` 构建成功。
2. iPhone 17 Pro 竖屏截图中无横向裁切、无按钮遮挡内容。
3. 页面核心路径可点击完成：主页入口、返回、主操作按钮。
4. 内容为空、内容较多、玩家战力不足三类状态不崩溃且有可读反馈。
